# Composable instructions: one generated AGENTS.md from every active loadout

Tier: **plan file + task briefs** (state-format change, overwrite protection, cross-cutting consumers). Built via `/orchestrate`.

## Problem (reproduced)

`activate base py` shows both instruction rows as `+`, but `AGENTS.md` links only to `instructions/AGENTS.base.md`. The cause is in `applyMultiPlan` (`src/core/render.ts:512-546`): it dedupes outputs by `targetPath`, and the first one wins. Instruction is the only kind where several artifacts share one target, so the second source is dropped without any message.

## Decisions

**Composition.** The instruction sources of all active loadouts are concatenated into one generated file per scope, and every instruction destination is a symlink to it.

| Scope | Generated file `G` | Destinations (symlink → `G`) |
|---|---|---|
| project | `<projectRoot>/.loadouts/AGENTS.loadouts-generated.md` | `AGENTS.md` (shared by every tool, Claude Code included) |
| global | `~/.config/loadouts/AGENTS.loadouts-generated.md` | `~/.claude/CLAUDE.md`, `~/.config/opencode/AGENTS.md`, `~/.codex/AGENTS.md`, `~/.pi/agent/AGENTS.md` (Cursor: none) |

Why `G` lives in the loadout root (`applyMultiPlan`'s `loadoutRoot` arg, i.e. `ctx.configPath`): it sits next to the sources it is built from and next to `.state.json`, which owns it. It gets gitignored with the state files. No tool discovers it on its own (none reads `AGENTS.*.md`, and the `instruction` kind's `detect` only matches `instructions/AGENTS.*`). It also never lands in package data for bundled loadouts, because those keep state at the activating scope.

- **Order:** loadouts in plan order, which is the activation order (`computeActivateSet` appends). Within a loadout, the resolved include order. This matches `compileRuntimeBundle` in `src/core/runtime.ts:163-207`.
- **Dedupe:** the identity is `fs.realpathSync(sourcePath)`. The first occurrence wins and keeps its loadout name. This also collapses the legacy `.loadouts/AGENTS.md` item that `loadResolvedLoadouts` (`resolve.ts:203-209`) attaches to every loadout.
- **Union semantics:** `G` holds every instruction source in the scope. Per-include `tools:` on an instruction only decides which destinations exist, not what they contain. Project scope already forces this (every tool reads the one `AGENTS.md`), and global uses the same rule so behaviour is consistent.
- **Single source:** always generate, never link straight to the source. This keeps one code path and one drift model, and the header and markers (the main defence against misplaced edits) are always there. The symlink target also stays stable when a second loadout is added. Editing through the symlink was never reliable anyway: Claude Code's Edit/Write tools refuse to write through symlinks (per the Claude memory docs).
- **Zero sources:** no `G` and no destinations. Stale ones are pruned, and `G` is deleted.
- **Bodies are verbatim:** frontmatter is not stripped. Each body is the source with trailing whitespace trimmed (`raw.replace(/\s+$/, "")`). There is no timestamp in the file, so the content (and its hash) stays deterministic.

**Generated format (frozen; tests assert it byte-for-byte):**

```
<!--
  Generated by loadouts. Do not edit this file.
  `loadouts sync` will not overwrite local edits here; it reports them instead.
  Edit the source named in each section, then run `loadouts sync`:
    - .loadouts/instructions/AGENTS.base.md (loadout: base)
    - .loadouts/instructions/AGENTS.py.md (loadout: py)
-->

<!-- loadouts:begin base · .loadouts/instructions/AGENTS.base.md -->
<body>
<!-- loadouts:end base · .loadouts/instructions/AGENTS.base.md -->

<!-- loadouts:begin py · .loadouts/instructions/AGENTS.py.md -->
<body>
<!-- loadouts:end py · .loadouts/instructions/AGENTS.py.md -->
```

Sections are joined by one blank line, and the file ends with a single `\n`. `displayPath` is the source path relative to `projectRoot` when it is inside it. Otherwise it is the absolute path with `os.homedir()` replaced by `~`; global sources show as `~/.config/loadouts/instructions/…`.

**Claude Code.** The `CLAUDE_WRAPPER` generator is removed.
- Project: Claude ≥ v2.1.277 reads `AGENTS.md` natively, in its default `claude-md-or-agents-md` mode, when no `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` exists in the working directory or any directory above it. So the project target becomes `AGENTS.md`.
- Global: the docs only define `~/.claude/CLAUDE.md` for user memory. They never mention `~/.claude/AGENTS.md`, and `~/.claude/CLAUDE.md` does not suppress `AGENTS.md`. So the global target is `{base}/CLAUDE.md`, as a symlink to `G`, not a wrapper.
- The old global target `{home}/CLAUDE.md` (`~/CLAUDE.md`) was harmful. Claude treats it as an ancestor `CLAUDE.md` for every project under `~`, which **disables AGENTS.md reading in all of them**. The next `loadouts sync -g` deletes it as a stale managed entry, and the troubleshooting docs explain this.

**Global target fixes, checked against each tool's docs:**
- codex: `{home}/AGENTS.md` → `{home}/.codex/AGENTS.md`.
- pi: `{home}/AGENTS.md` → `{base}/AGENTS.md`, which is `~/.pi/agent/AGENTS.md`.
- cursor: becomes project-only (`scopes: ["project"]`). Cursor's User Rules are UI-only; it has no file.
- opencode: unchanged.

The old `~/AGENTS.md` and `~/CLAUDE.md` entries are pruned on the next global sync.

**The editing problem.** Loadouts never discards local edits to the composed file without the user asking.
- **Edit detection, at apply time.** Two cases count as an edit:
  - **edited:** a tracked composed entry exists, `G` exists, and `hashFile(G) !== entry.renderedHash`.
  - **replaced:** a tracked instruction destination exists as a regular file (not a symlink) and `hashFile(D) !== entry.renderedHash`. This rule also covers pre-migration entries.
- **Default:** keep the edited files. `G` and every instruction destination are left untouched, and their old manifest entries carry over into the new state. All other outputs still apply. The command prints an attribution report and sets `process.exitCode = 1`.
- **Attribution.** The edited content is parsed with the begin/end markers. A section counts as edited when `hashContent(body) !== recorded source hash`. Its diff runs from the current source body to the edited body, under the heading "from `<loadout>` (`<displayPath>`)". If the markers are damaged, or the set of sections differs from what was recorded, the report falls back to one whole-file diff (owner `null`) from the freshly composed content to the edited content.
- **`--force`** on `sync` and `activate` writes the edited content to the backup, then overwrites.
- **Removal never holds edits:** deactivating the last instruction, `clear` or `remove` backs up an edited `G` (or a replaced destination), deletes it, and warns.
- **Backup file:** `<loadoutRoot>/AGENTS.loadouts-generated.md.bak`, overwritten on every backup and gitignored. When several files are backed up together, each one is preceded by a line `<!-- loadouts:backup <displayPath> <ISO time> -->`.
- **Write-back** (copying edited sections into their sources automatically) is **not** in this plan. The marker format is designed so that it can be added later.

**State fan-in.** `ManifestEntry` gains an optional field, `sources?: Array<{ path: string; hash: string }>`. A composed destination entry looks like this:
- `sourcePath = G`, which keeps `detectDrift`'s misdirected/broken/hash checks working unchanged.
- `mode: "symlink"`.
- `renderedHash = hash(G content)`.
- `sources`: the inputs in order, using the first-seen `spec.sourcePath` and the trimmed-body hash.

`G` itself is **not** a manifest entry. Its lifecycle comes from the composed entries: it is written whenever a composition exists, and deleted when composed entries go away. Old state files still parse, because the field is optional. Consumers that ask "which artifact does this entry belong to" switch to two new helpers, `entrySources` and `expandDriftBySource`.

**Unmanaged collisions** (an `AGENTS.md` exists that no state entry tracks) are decided in `planRender` for instruction specs. Adopt it if it is a symlink whose realpath lies inside the state root (`fs.realpathSync(statePath ?? loadout.rootPath)`). That covers links made by the fallback script and links to `G` left behind by a lost state file; nothing is lost, because the content lives in the sources or `G`. Anything else is shadowed, as today (for example a hand-written committed `AGENTS.md`). An untracked `G` whose content differs from the new composition is backed up, then overwritten, with a warning.

**Change table.** Rows stay per source. Composed change keys are `changeKey(spec) = targetPath + "\0" + sourcePath`. For a composed entry with no `sources`, the old sources are taken to be `[{path: entry.sourcePath, hash: entry.renderedHash}]`.
- A source not among the old entry's sources gets `+`.
- A source whose hash changed gets `~`; an unchanged one gets `✓`.
- An old source no longer present goes into `removed`.
- A source that was held back by an edit gets the new ChangeType `held`, shown as `!` in red.

So `activate py` on top of `base` now shows py `+` and base `✓`.

**Warnings** (`ApplyResult.warnings`, also printed by dry-run):
1. **Codex size:** the composed file exceeds a destination tool's `instructions.maxBytes`. For Codex that is 32768 bytes (`project_doc_max_bytes`). Message: `AGENTS.md is 41.2 KiB; codex reads only the first 32 KiB (project_doc_max_bytes). Trim instructions or raise project_doc_max_bytes in ~/.codex/config.toml.`
2. **Claude suppression** (project scope): a destination tool lists files in `instructions.suppressedBy` (for claude-code: `["CLAUDE.md", "CLAUDE.local.md", ".claude/CLAUDE.md"]`), and one of them exists under `projectRoot`. Message: `Claude Code reads CLAUDE.md instead of AGENTS.md while CLAUDE.md exists; move its content into an instruction source and delete it.`
3. Backups written.

**Gitignore.** `.loadouts/.gitignore` adds `AGENTS.loadouts-generated.md` and its `.bak` to `LOADOUTS_STATE_PATHS` (`src/lib/gitignore.ts:49`). Destinations keep their current treatment (project `AGENTS.md` goes in the managed root `.gitignore` section). `CLAUDE.md` drops out of that section automatically, because no tool targets it at project scope any more. `G` is gitignored, so on a fresh clone `AGENTS.md` comes from the fallback script or the first `loadouts sync`.

**Fallback script** (`src/core/fallback.ts:34-53`): delete the `CLAUDE.md` block. Instructions keep linking the first `instructions/AGENTS.*.md`. That link is adoptable under the collision rule above, so the first real sync repoints it to `G`.

**Rejected:** composing inside `planRender`. Plans are per loadout, and composition is inherently cross-loadout; status, check and TUI all depend on per-loadout plans staying per item.

`composeInstructions`:
1. Walk `plans` in order, then `plan.outputs` in order, keeping outputs where `isComposedKind(spec.kind)`.
2. Group destinations by `spec.targetPath`, collecting their tools.
3. Collect sources, deduped by realpath, using the first-seen loadout name.
4. Read each source, trim trailing whitespace, and hash it with `hashContent` from `src/lib/fs.ts`.
5. Build the content in the frozen format.
6. Set `generatedPath = path.join(loadoutRoot, GENERATED_INSTRUCTIONS_FILE)`.
7. Compute the Codex-size and Claude-suppression warnings. Iterate destination tools with `registry.getTool(t)?.instructions`; check `suppressedBy` only at project scope, as `fileExists(path.join(projectRoot, rel))`. Each warning names the destination's display path.
8. Return `null` when there are no composed outputs.

`detectInstructionConflicts`:
- Composed state entries are entries where `isComposedKind(kind)`.
- **edited** (one conflict): any of them has `sources`, `entry.sourcePath` exists, and `hashFile(entry.sourcePath) !== entry.renderedHash`.
- **replaced** (one conflict per destination): the entry's target exists, is not a symlink and not a directory, and `hashFile(target) !== entry.renderedHash`.
- Edits come from `parseSections(edited)`. A section maps to a source by `displayPath`. It is edited when `hashContent(body) !== recorded hash`. `before` is the current trimmed source body, or `""` if the source no longer exists. If `parseSections` returns `null`, or the parsed display paths differ from the recorded ones, return a single edit with `owner: null`, `before = composition?.content ?? ""`, `after = edited`.
- Without a composition, the recorded display paths come from the entry's `sources`, computed by the same displayPath function.

`parseSections`: match the regex `/^<!-- loadouts:begin (.+?) · (.+?) -->\n([\s\S]*?)\n<!-- loadouts:end \1 · \2 -->$/gm`. Return `null` if no section is found or any begin marker has no matching end.

`applyMultiPlan` steps. Reuse the existing code at `render.ts:519-632`; collapse `applyPlan` (lines 419-497) into a call to it.
1. Split composed outputs out of the merge map. Normal outputs keep today's logic.
2. Run `composition = composeInstructions(...)`. If there is no `options.force`, run `conflicts = detectInstructionConflicts(existingState, composition, projectRoot)`.
3. **If held** (conflicts exist and no force): the composed state entries carry over unchanged. Their targets are excluded from stale pruning. Neither `G` nor any destination is written. Every composed plan spec's `changeKey` goes into `changes.held`.
4. **Otherwise:**
   - Collect the content to back up: an edited tracked `G` (forced, or no longer composed), a replaced destination (forced, or removed), or an untracked existing `G` whose content differs from the new composition.
   - Write the backup and add a warning.
   - Write `G` if a composition exists; else delete `G` if it exists.
   - For each destination: `prepareOutputTarget` + `createSymlink(G, D)`.
   - Prune old composed destinations that are no longer present.
5. Manifest entries per destination: `{ tools, kind: "instruction", sourcePath: G, targetPath, mode: "symlink", renderedHash: composition.hash, sources }`.
6. Change keys per the "Change table" rules in Decisions; normal outputs keep `targetPath`.
7. `byTool` counts each destination's tools.
8. `warnings = composition.warnings` plus backup warnings.

`removeManaged`: for composed entries, back up the files that hold edits (same rules as above), delete the destination, then delete `G` once, and return `warnings`.

Gitignore: `const LOADOUTS_STATE_PATHS = [".fallback-applied", ".state.json", GENERATED_INSTRUCTIONS_FILE, GENERATED_INSTRUCTIONS_BACKUP];` (import from `../core/instructions.js`).
